# راهنمای اجرای بسته نهایی دمو

این بسته دو روش اجرای یکسان دارد: اجرای Native ویندوز بدون Docker و اجرای Docker. پوشه نهایی بعد از بسته‌بندی در مسیر `release/demo/` ساخته می‌شود.

## پیش‌نیاز رایانه مقصد

- ویندوز ۱۰ یا ۱۱ نسخه ۶۴ بیتی
- اتصال اینترنت برای ارتباط با سرویس مدل زبانی (LLM)
- فضای خالی کافی برای کپی پوشه دمو روی حافظه داخلی

برای اجرای **Native** نیازی به نصب Python، pip، محیط مجازی، Docker Desktop، PyTorch یا Sentence Transformers نیست. این موارد همراه برنامه بسته‌بندی می‌شوند.

برای اجرای **Docker** باید Docker Desktop نصب و در حال اجرا باشد و روی حالت Linux containers قرار داشته باشد.

## اجرای دمو

۱. کل پوشه `demo` را از فلش روی حافظه داخلی رایانه کپی کنید. فقط فایل اجرایی را جداگانه کپی نکنید؛ همه پوشه‌های کنار آن لازم هستند.

۲. روی فایل `START-DEMO.bat` دوبار کلیک کنید.

۳. یکی از دو روش را انتخاب کنید:

- گزینه ۱: اجرای Native ویندوز؛ بدون Docker
- گزینه ۲: اجرای Docker؛ نیازمند Docker Desktop

۴. راه‌انداز این اطلاعات را می‌پرسد:

- کلید API سرویس مدل زبانی
- شناسه دقیق مدل در سرویس‌دهنده
- آدرس پایه API؛ برای OpenAI می‌توانید خالی بگذارید
- پورت محلی سایت؛ مقدار پیش‌فرض Native برابر ۸۰۰۰ و مقدار پیش‌فرض Docker برابر ۸۰۸۰ است

کلید API با ورودی امن دریافت می‌شود و در فایل یا پوشه فلش ذخیره نمی‌شود. کلید فقط تا پایان اجرای برنامه در محیط همان فرایند قرار دارد.

## اجرای Native چه تفاوتی دارد؟

در حالت Native، برنامه FastAPI، وب‌سایت، ویجت، مدل E5 و بازیابی اسناد روی همان رایانه اجرا می‌شوند. Python و وابستگی‌های برنامه داخل پوشه اجرایی قرار دارند؛ بنابراین نصب جداگانه آن‌ها لازم نیست.

اولین اجرا ممکن است چند دقیقه طول بکشد، چون مدل E5 در حافظه بارگذاری می‌شود. پنجره مشکی راه‌انداز را هنگام ارائه باز نگه دارید. برای پایان دمو Enter را در همان پنجره بزنید.

## اجرای Docker چه تفاوتی دارد؟

در حالت Docker، imageهای از پیش ساخته‌شده بارگذاری می‌شوند و سرویس API و وب‌سایت داخل کانتینر اجرا می‌شوند. Docker Desktop باید پیش از اجرای دمو آماده باشد.

راه‌انداز منتظر آماده‌شدن API و مدل E5 می‌ماند، سپس سایت را در مرورگر باز می‌کند. برای پایان دمو Enter را در پنجره راه‌انداز بزنید تا کانتینرها متوقف شوند.

## ارتباط اینترنت و اطلاعات محرمانه

مدل embedding یعنی E5 و ایندکس بازیابی به‌صورت محلی اجرا می‌شوند. فقط تولید پاسخ نهایی به API سرویس‌دهنده مدل زبانی ارسال می‌شود؛ بنابراین برای کارکرد چت، رایانه باید به همان سرویس‌دهنده دسترسی اینترنتی داشته باشد.

کلید API داخل بسته قرار ندارد و در فایل `.env` یا کد سایت ذخیره نمی‌شود. آن را در اختیار دیگران قرار ندهید.

## ساخت بسته روی رایانه توسعه

ساخت نسخه Native باید روی ویندوز ۶۴ بیتی انجام شود. برای ساخت هر دو گزینه، Python 3.13، 3.14 یا 3.12، مدل E5 و اسناد دانش باید روی رایانه توسعه موجود باشند و Docker Desktop با Linux containers اجرا شود. اسکریپت بسته‌بندی به‌ترتیب اولین نسخه نصب‌شده را انتخاب می‌کند.

از ریشه پروژه، PowerShell را باز کنید و اجرا کنید:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\package_demo.ps1
```

اسکریپت یک محیط بسته‌بندی جداگانه با نسخه پشتیبانی‌شده Python می‌سازد، PyTorch مخصوص CPU را نصب می‌کند، ایندکس را بازسازی می‌کند، نسخه Native را می‌سازد و سپس imageهای Docker را ایجاد و بررسی می‌کند. کلید API برای ساخت بسته لازم نیست.

خروجی نهایی:

```text
release/
└── demo/
    ├── START-DEMO.bat
    ├── START-NATIVE.ps1
    ├── README.md
    ├── native/
    │   ├── PersianSiteAssistant.exe
    │   ├── _internal/
    │   ├── data/
    │   ├── models/
    │   ├── website/
    │   └── widget/
    └── docker/
        ├── START-HERE.ps1
        ├── compose.yaml
        └── images.tar
```

کل پوشه `release/demo/` را روی فلش کپی کنید. این پوشه ممکن است به‌دلیل وجود PyTorch و مدل E5 حجیم باشد.

## اگر دمو شروع نشد

- در حالت Native مطمئن شوید کل پوشه `native` همراه فایل‌های `_internal`، `data`، `models`، `website` و `widget` کپی شده است.
- در حالت Docker مطمئن شوید Docker Desktop اجرا شده و روی Linux containers است.
- در هر دو حالت، شناسه مدل، کلید API و دسترسی شبکه به سرویس‌دهنده LLM را بررسی کنید.
- گزارش شروع برنامه در همان پنجره راه‌انداز نمایش داده می‌شود.
- اگر پورت پیش‌فرض اشغال باشد، هنگام اجرا پورت دیگری وارد کنید.

شرکت، محصولات، سناریوها و بازه‌های قیمت داخل سایت کاملاً فرضی و فقط برای نمایش هستند.
